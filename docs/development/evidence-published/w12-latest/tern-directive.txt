1. 次タスク決定
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

次タスクは MP-IMG2-W12 とする。

単一目的：
同一の4K・8-bit grayscale画素を持つJPEGとPNGを、
既存Windows WIC OnLoad経路でそれぞれ実decodeし、
ROI出力・全フレームadmission・process-memory観測を
同条件で比較する。

W11では4K JPEGのROI検証と16K JPEGの予算拒否を確認した。
W12では入力寸法・期待画素・ROI・観測境界を揃え、
codec/containerが異なる場合の実際のWIC観測差を記録する。

実験の目的はcodec別の観測事実の取得である。
decoder採用、性能優劣の決定、メモリSLO批准ではない。

【選定根拠】

既存実装には以下が存在する。

- W2：有界single-boundary workerと停止・回収処理
- W4：OnLoad後のROI出力
- W6：process-memory sampler
- W7：4K PNGの実decodeと予算検査
- W11：4K grayscale JPEG、DC/block-coordinate oracle
- W11：実Windows JPEG ROI・process-counter観測

WICの新API、COM、unsafe、外部decoderを追加せず実行できる。

一方、現行のWIC probeはOnLoadで全フレームをmaterializeする。
true partial decodeを検証する実経路は存在しない。

したがって、W12でtrue partial decodeの成功や
WIC内部scratchの測定を要求しない。

4. 入力fixture
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

対象寸法：
4096 × 4096 pixels

Source depth：
8-bit grayscale

Fixture J：
W11の既存jpeg_gray_4kを再生成する。

Fixture P：
Fixture Jの宣言されたDC-only画素パターンと
全画素が一致するlossless grayscale PNGを
W12で新規生成する。

JPEGは既存W11 fixture bytes・SHA-256と一致すること。

PNG生成要件：

- streaming row construction
- 8-bit grayscale PNG
- bounded zlib compression
- 正しいPNG signature / IHDR / IDAT / IEND
- CRC・chunk lengthの検証
- 全フレームRGBAの一括生成禁止
- 既存fixtureの上書き禁止
- exclusive create
- encoded byte sizeとSHA-256を保存

PNGがJPEG decoderの出力を再符号化したものに
なってはならない。

独立oracleは以下を確認する。

1. JPEG bitstreamのDC/EOB・padding・EOI
2. PNG chunk/CRC/inflation
3. 両方の宣言寸法・depth
4. JPEGから導出した各座標の期待画素
5. PNG全画素が同じ座標の期待画素と一致すること

producerの自己申告hashだけではfixtureを承認しない。

2入力の全画素同一性が成立しない場合はHOLDする。

【repeat】

独立したfresh work rootで2回実行する。

各回：
6 cases / 6 serial worker lifetimes

合計：
12 worker executions

2回の結果で以下が一致すること。

- fixture identity
- source geometry
- admission classification
- decoder/source-format observations
- ROI geometry
- PNG output bytesとRGBA pixels
- 独立oracleの比較結果

process-memoryの数値一致は要求しない。
観測値の差はそのまま保持する。

7. Process-memory比較の意味
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

正常ケースS01～S04で
既存W6 samplerを使用する。

採取するもの：

- worker PID
- process start identity
- executable identity
- source fixture SHA-256
- stage identity
- working_set_bytes
- private_bytes
- observer clock
- sampling window
- capture completeness
- process lifetime

比較するもの：

A. JPEG vs PNG、同じ1×1 ROI
B. JPEG vs PNG、同じ256×256 ROI
C. 同codecでのROIサイズ差
D. repeat間の観測範囲

結果は各processの観測値を維持する。

比較結果に付ける分類：

OBSERVED_WHOLE_PROCESS_DIFFERENTIAL

禁止する解釈：

- WIC-only allocation delta
- decoder internal scratch
- allocator reservations
- true concurrent allocation peak
- same-process before/after allocation delta
- causal codec memory advantage
- product memory SLO

各workerは独立process lifetimeである。
異なるworkerのprocess counter差分を
同一process内のallocation変化と呼ばない。

観測が欠けた場合は推定値を補わず、
該当runを不完全としてHOLDする。
