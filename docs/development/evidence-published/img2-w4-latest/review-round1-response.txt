5. 指摘事項
A-W4-01 — Bgr555対照をBgr565として誤認定できる

種別：ACTIONABLE NON-BLOCKING

対象：apps/desktop/devtools/img2/w4_region_verify.py:197–229

検証器は、probe_result.pixel_format == "Bgr565"の場合に、channel depth 6、storage 16 bppを確認しています。

しかし、そのformatが元BMPのbitfield masksおよびadmitted stageのformat情報と一致しているかを確認していません。

独立改変テストで次を再現しました。

roi_full_bgr555_controlの元BMP、mask、出力PNGは変更しない。

probe_result.pixel_formatをBgr555からBgr565へ変更する。

bits_per_channelを5から6へ変更する。

stdoutを変更後のprobe_resultと一致させる。

verify()を実行する。

結果：

プレーンテキスト
fixture_id            = bmp555_control
actual BMP masks      = 0x7C00 / 0x03E0 / 0x001F
claimed pixel_format  = Bgr565
claimed channel depth = 6

verify.ok             = true
bgr565_limited_proof  = true

逆方向、すなわち実Bgr565をBgr555として記録した場合も検証成功しました。

これは実Native結果の誤りではありません。しかし、検証器が能力表のformat帰属を誤った値で認定できるため、W4の受入条件に関係します。

最小修正条件

既知fixtureについて、元BMPのbitfield masksから期待formatを独立に確定し、probe_resultのpixel formatとdepthに照合してください。

少なくともBgr565はBgr565 / 6 / 16、Bgr555対照はBgr555 / 5 / 16を必須とします。admitted stageのdepth・storage値もprobe_resultと照合してください。

両方向の誤認定を負例へ追加し、必ずok=falseとなることを確認してください。

WIC decoderやpixel oracleを変更する必要はありません。

A-W4-02 — cancellationの原因・終了コード不整合を検証器が許容する

種別：ACTIONABLE NON-BLOCKING

対象：apps/desktop/devtools/img2/w4_region_verify.py:167–180

W4検証器はstop_confirmed、hold成立、kill発行、reap成立を検査しますが、W2で確定した状態機械のすべての条件を検査していません。

独立改変テストでは、実Native記録のcancel_roiとtimeout_roiについて、以下が再現しました。

両ケースで同じ結果です。

特に、exit_after_request=1を保持したままworkerのexit_code=0に変更しても、検証器は成功します。

つまり、実際のプロセス停止結果が不整合でも、confirmed cancellationとして認定できる経路が残っています。

なお、提出された実Native記録自体はcause=boundary_hold、kill発行済み、終了コード1で整合しています。

最小修正条件

W4検証器に、W2の確定済み停止契約を反映してください。

cause=boundary_hold、method=direct_child_terminate_wait、kill_errorなし、waited=true、停止要求時刻の存在、reap結果とworker終了コードの一致、非ゼロ終了を必須とします。

requested_ns、observed_ns、started_ns、exited_nsについても、既存の単調時計契約と整合することを確認してください。

また、提出されたcancellation-record.jsonはcases=[]ですが、Native reportにはcancel/timeoutが各1件あります。独立証拠として使用するなら、両ケースへの参照を保持してください。

実際のWorker.stop()やWIC処理を再設計する必要はありません。W4 verifierと限定負例テストの修正で対応できます。

7. 限定closure判断

今回の実測から、ROI outputの画素正確性と、ROIによるfull-frame予算迂回が発生しないことは裏付けられています。

また、true partial / sequential / tiled decodeを未証明のまま維持する分類も適切です。

しかし、A-W4-01とA-W4-02により、能力帰属とcancellationの不正記録を検証器が受け入れるため、W4 LIMITED TECHNICAL COMPLETIONの0/0/0 closureは保留します。

今回の修正はW4 verifier・限定テスト・必要な証拠整備に絞れます。SOURCEが変更される場合は新しい固定候補に対する独立Gateとレビューが必要です。

16K、内部scratch、真の同時peak、cooperative decoder cancellation、region/sequential/tiled、ICC/orientation、JPEG絶対raster、full Decode/Upload、Runtime、measured R0は引き続き未達であり、今回の指摘件数には含めません。

今回のレビューでは、未push Git commit全体の取得、Windows WIC、GUI、Refine Gateの実機再実行は行っていません。
