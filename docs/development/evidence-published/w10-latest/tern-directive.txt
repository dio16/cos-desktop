次タスク：MP-IMG2-W10 — JPEGメタデータ・色変換の実decode差分検証

優先度：P1 / 推奨：単一タスクで実行

W9の次は、JPEG対応範囲をさらに拡張するよりも、EXIF OrientationとICCプロファイルがWIC/GDI+のデコード結果に与える影響を検証することを推奨します。

W8・W9で確認したピクセル一致が、色管理や向き情報を含むJPEGでも成立するかを切り分け、将来のdecoder選定に必要な判断材料を取得します。

1. 単一の目的

MP-IMG2-W10：JPEG metadata interpretation differential

Windows WIC/GDI+によるJPEG実decodeについて、メタデータの有無・内容によるピクセル出力差を再現可能な証拠として記録する。

今回も LIMITED TECHNICAL COMPLETION のみを目指し、色管理方針や製品decoderの採用は行いません。

3. 受入基準

1. 独立した入力・出力検証
EXIF/ICCを有界に解析し、生成fixtureの実体・メタデータ・期待値を照合する。decoder同士の一致だけを正解としない。

2. 実Windows比較
WIC/GDI+の双方を実行し、decode結果、出力寸法、ピクセルdigest、metadataの解釈、失敗理由をケース単位で記録する。

3. fail-closed
検証不能・不一致・切断・不正なメタデータを、根拠なく content_verified に昇格させない。decoderが入力を許容した事実と、検証成功を区別する。

4. 有界実行・証拠
W9のtimeout、出力容量上限、worker cleanup、stale-output防止、source/evidence SHA対応を維持する。独立した再実行で決定論的な項目を照合する。

5. 独立Gateとレビュー
新しい固定候補SHAで既存の該当5 Gateを実行。Gate全成功、実Windows証拠、Tern独立評価 PASS 0/0/0 を必要条件とする。過去Gateの流用は禁止。

ICCの色変換が行われたかどうかは、独立した色基準によって検証できた場合のみ確定します。できなければ NOT_MEASURED とします。

4. 前提条件と停止条件

開始前に、ローカルHEAD、W9製品候補、disposition、5 Gateの整合性を確認してください。GitHubで確認できるリモートdevはW2記録時点であり、未pushのW9最新版は今回直接照合できていません。

次の場合は実装を停止し、HOLDとして報告します。

W9の承認済み挙動を変更する必要が生じた

有効なICC fixtureや独立参照値を確保できない

新規依存、unsafe、製品decoder変更が必要になった

Gate対象と検証証拠のSHAが一致しない

実Windowsの必要ケースが実行できない

preflight=unknown、Build executable=NOT_CAPTURED は証拠が取得できるまで維持し、暗黙にPASSへ変更しません。

devへのpush、main統合、release、製品ポリシー批准は本指示では認可しません。
