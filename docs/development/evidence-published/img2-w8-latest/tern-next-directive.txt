4. W8の選択理由と技術目標
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

DC-MP-IMG2の正典は、
per-codec decoder admissionと比較を要求する。

候補集合:

A. Windows Imaging Component / GDI+
B. FFmpeg 8.0 external experimental harness

FFmpegの製品採用は別のdependency/licence decisionを要する。

これまでのW1～W7で成立した画素検証は、
主としてPNG、BMP24、Bgr565である。

JPEGについては、decoderが出力した画像を
別のPNGに保存できるだけでは、
絶対画素正当性の証明にならない。

またJPEGには次の差異がある。

- baseline/progressive
- sampling layout
- IDCT実装
- rounding
- YCbCr→RGB変換
- decoder固有の出力format
- EXIF orientation
- ICC/profile handling
- malformed inputの許容差

このためW8では次の技術証拠を新しく構築する。

A. 既知の復元画素値を持つ小型JPEG fixtureの実decode。

B. 通常の非一様JPEGにおけるWIC/GDI+実出力比較。

C. baseline/progressiveのcapability分類。

D. JPEG source bit depth、sampling、dimensions、
   decoder identity、versionの記録。

E. 独立referenceが成立するcaseと、
   decoder間の相対比較だけのcaseを区別する。

F. malformed JPEGでのdecoder outcomeと
   content verificationを分離する。

G. JPEGでもfull-frame admission、
   resource budget、output publication、
   stop contractが維持されること。

W8の目標は、JPEGの限定クラスについて
codec capabilityとpixel correctnessの証拠を増やすこと。

全JPEGのabsolute raster correctness、
製品decoder採用、colour policy批准は非対象。

6. JPEG fixtureと独立reference
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

基本fixture集合は最大12 source cases。

Class A:
絶対画素の検証を狙うdeterministic fixture。

- 8-bit grayscale baseline JPEG
- DC-only JPEG
- 定数輝度block
- 複数の既知輝度値
- 少なくとも2つの寸法クラス

DC-only baseline JPEGでは、
期待画素値をJPEGの係数、量子化表、
level shiftから独立に導く。

符号化実装から復号期待値をコピーしない。

JPEGのnormative semanticsに基づいて
厳密な期待値を導出できるcaseだけを
ABSOLUTE_REFERENCE_ELIGIBLEとする。

丸め・IDCT・clamping等の差異によって
一意の8-bit値を証明できないcaseは、
無理にabsolute correctnessへ分類しない。

Class B:
非一様な通常JPEG。

- baseline RGB/YCbCr JPEG
- 4:4:4
- 4:2:0
- 256×256
- 1024×1024

元encoded bytesとJPEG markersから:

- SOI/EOI
- SOF
- precision
- dimensions
- component count
- sampling factors
- quantization tables
- Huffman tables
- SOS
- restart markers
- segment bounds

を独立解析する。

Class C:
progressive JPEG。

- 256×256
- 1024×1024

対応する正当なencoded fixtureを
固定のbytes/SHA256付きで用意する。

生成手段が既存の承認済み環境にない場合、
未承認dependencyを導入しない。

既存の信頼可能なfixtureを使えなければ
当該classをNOT_RUNとして記録し、
W8全体の受入範囲から勝手に削除しない。

Class D:
malformed JPEG。

- truncated scan
- invalid marker/segment length

これらはdecoder側が拒否するとは限らない。

WIC/GDI+が画素を返しても、
元encoded構造や独立referenceが成立しなければ、
content_verifiedへ昇格しない。

各fixtureには以下を保存する。

- fixture_id
- provenance
- encoder/generator identity
- input bytes/SHA256
- SOF variant
- width/height
- precision
- sampling factors
- encoded length
- declared decoded requirement
- reference class
- reference authority
- expected RGBA digest（成立する場合のみ）
- malformed reason（該当する場合）

「元PNGの画素」と「JPEG復元後の画素」を
同一視してはならない。

JPEGは非可逆圧縮である。

7. Independent referenceの成立条件
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Referenceを次の3段階へ分類する。

ABSOLUTE_VERIFIED:
固定encoded JPEGに対し、
独立した係数・pixel referenceが成立し、
actual decoded rasterが全画素一致したcase。

DIFFERENTIAL_VERIFIED:
WIC/GDI+等の実出力を同じcanonical formatへ
正規化して全画素比較できたcase。

NOT_VERIFIED:
独立reference不成立、
出力未取得、
decoder failure、
結果不整合、
検証不能のcase。

重要:

DIFFERENTIAL_VERIFIEDは
ABSOLUTE_VERIFIEDではない。

2 decoderのpixel digestが一致しても、
共通の間違いを排除できない。

逆にdigest不一致だけで、
どちらか一方を不正と断定しない。

比較結果には:

- exact match count
- differing pixel count
- differing channel count
- maximum channel absolute difference
- mean absolute channel difference
- first differing coordinate
- decoder output format
- normalization method

を記録する。

JPEG decoder間のrounding/IDCT差を
恣意的な閾値でPASSにしてはならない。

許容誤差の批准は本タスクの権限外。

絶対値の一致が要求されるcaseでは
独立referenceとのexact一致を要求する。

相対比較caseでは
差異の正確な測定・記録を受入条件とする。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

必須:

- WIC実decode
- GDI+実decode
- Fixed fixture identity
- Fixed SOURCE identity
- Executable identity
- Decoder identity
- Full-frame admission

Native実行前にSOURCEを固定する。

各decoder legには:

- candidate
- decoder/version
- source SHA256
- fixture SHA256
- executable SHA256
- PID/process lifetime
- admission result
- materialization status

失敗したlegを別decoderの成功で埋めない。

GDI+とWICの処理段階が異なる場合、
同名のstageを捏造しない。

実測不能なstageはNOT_MEASUREDとする。

W2の人工hold時間を
decoder latencyに加算しない。

decoder latencyを測る場合は、
実際のdecode呼出しの開始・終了時刻を
instrumentationで確認する。

取得できない場合:
NOT_MEASURED

各batchは300秒以内に限定する。

24 legsを一度に無制限実行しない。

worker回収とwork root ownershipを維持する。

正常decodeでは必ず:

の整合を要求する。

Malformed inputでは
worker outcomeとoracle classificationを
条件付きで独立検証する。

最低限のnegative mutation:

01. source width改変
02. source height改変
03. JPEG SOF precision改変
04. sampling factor改変
05. container marker改変
06. input SHA256改変
07. decoder identity改変
08. decoder version改変
09. decoded requirement過少申告
10. BGRA32 requirement過少申告

12. admission stage偽装
13. decoder outcome偽装
14. output bytes偽装
15. output SHA256偽装
16. decoded output未公開なのに成功申告
17. expected RGBA digest改変
18. actual RGBA digest改変
19. DIFFERENTIAL_ONLYをABSOLUTEへ昇格
20. decoder間一致をabsolute proofへ昇格
21. mismatch countをゼロへ偽装
22. first mismatch coordinateを改変
23. normalization条件不一致を隠す
24. ICC metadataをprofile_appliedへ昇格
25. orientation tagをrotation_appliedへ昇格
26. malformed inputをCONTENT_VERIFIEDへ昇格
27. unsupportedをdecodedへ変更
28. traceに未解析tailを追加
29. incomplete captureをcompleteへ変更
30. process identityを別workerへ交換
31. Native SOURCEを旧W7へ差し替える
32. timeoutをconfirmed cancellationへ偽装

全負例を実際のverify()へ投入する。

負例のうちtraceに埋め込まれた値を変える場合、
trace payload・length・SHA256を整合させた
coherent mutationも含める。

単なるdigest mismatchによる拒否だけで
算術・状態整合の検証成立を主張しない。

Private Git objectsがない構造replayでは:

source_identity_verified=false
closure_eligible=false

を維持する。

DESIGN_BLOCKED:
未承認の設計判断が必要。

AUTHORITY_BLOCKED:
Caller権限外の操作が必要。

DEPENDENCY_BLOCKED:
新規依存関係・ライセンス判断が必要。

SAFETY_BLOCKED:
実験上限やworker回収の安全性を保証できない。

NOT_RUN:
実行していない。

NOT_MEASURED:
必要な測定値が取得できない。

NOT_VERIFIED:
観測はあるが正当性を証明できない。

FAILED:
実行結果が失敗。

停止は該当scopeへ限定し、
独立に実行可能な既承認scopeは継続する。
