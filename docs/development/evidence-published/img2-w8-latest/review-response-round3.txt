4. 残存指摘
A-W8-R3-01 — Malformed WICのworker outcome欠落を受理する

分類：ACTIONABLE NON-BLOCKING

対象：apps/desktop/devtools/img2/w8_jpeg_verify.py:444–454

今回、worker・probe・terminal outcomeの一致条件が追加されています。しかし、次の条件式ではworker.outcomeの存在を必須としていません。

Python
実行
if record.get("outcome") is not None:
    need(record["outcome"] == observed, ...)

独立再現

malformed_truncatedのWIC workerからoutcomeフィールドのみを削除しました。

Python
実行
worker.pop("outcome")

実際のverify()結果：

プレーンテキスト
ok = true
tamper_not_verified = 2
source_identity_verified = false
closure_eligible = false

本来decodedとして記録されるべきworker outcomeが欠落しているにもかかわらず、検証成功として受理されています。

さらに、malformed分岐ではstages[-1]を直接読んでおり、正常decodeで使っている_trace()によるraw traceのSHA256・解析済みstageとの一致検証が行われていません。これはSOURCE上で確認できる同じ証拠認定条件の不足です。

最小修正条件

Malformed WICのworker.outcomeを必須とし、probe_result.outcomeとの厳密一致を要求する。

_trace()を適用し、raw trace・解析済みstages・terminal outcomeを結合する。

Decodedとfailureの両経路について、outcome欠落およびtrace不整合を拒否する負例を追加する。

TAMPER_NOT_VERIFIEDの内容分類は変更しない。

A-W8-R3-02 — GDI+のoutput_bytes欠落を受理する

分類：ACTIONABLE NON-BLOCKING

対象：apps/desktop/devtools/img2/w8_jpeg_verify.py:288–294

今回、GDI+のwidth/heightとinput_bytesは必須で照合されました。一方、output_bytesは次の任意条件です。

Python
実行
if result.get("output_bytes") is not None:
    need(result["output_bytes"] == len(data), ...)

このため、値を偽装した場合は拒否しますが、フィールドそのものの削除は受理します。

独立再現

正常dc_gray_8x8のGDI+ legから次を削除しました。

Python
実行
leg["probe_result"].pop("output_bytes")

実際のverify()結果：

プレーンテキスト
ok = true
source_identity_verified = false
closure_eligible = false

実Native原本には正しいoutput_bytesが存在します。検証器が欠落を許すことだけが問題です。

最小修正条件

Python
実行
need(
    result.get("output_bytes") == len(data),
    "gdiplus_declared_output_bytes_mismatch"
)

output_bytes欠落を独立負例として追加してください。既存のgeometry、input bytes、実出力SHA256検査は維持します。
