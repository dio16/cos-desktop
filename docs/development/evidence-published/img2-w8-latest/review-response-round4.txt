5. 新たに確認した残存指摘
A-W8-R4-01 — Malformed WICの完了traceに未解析末尾を追加しても検証成功する

分類：ACTIONABLE NON-BLOCKING

対象：

apps/desktop/devtools/img2/w8_jpeg_verify.py:331–350 — _trace()

同ファイル:447–457 — malformed WICの検証

apps/desktop/devtools/img2/tests/test_w8_negative.py

Round 3の指摘どおり、raw traceと解析済みstageの結合、および終端probe_exitの確認は追加されています。

ただし、_trace()は最終改行までのJSON行を解析し、その後の未解析バイトをtrace_partial_bytesとして許容します。Malformed WIC経路では、正常decodeと異なり、完了traceに対してtrace_partial_bytes == 0を要求していません。

独立再現

現Nativeのmalformed_truncatedに対し、WIC workerのtrace末尾へGARBAGEを追加し、次の値を変更しました。

Python
実行
worker["trace_utf8"] += "GARBAGE"
raw = worker["trace_utf8"].encode("utf-8")
worker["trace_sha256"] = "sha256:" + hashlib.sha256(raw).hexdigest()
worker["trace_bytes"] = len(raw)
worker["trace_partial_bytes"] = 7

元のworkerはtrace_complete=true、終端probe_exit.complete=trueであり、trace_partial_bytes=0でした。

改変後の現行verify()の実結果は次のとおりです。

プレーンテキスト
ok = true
source_identity_verified = false
closure_eligible = false
tamper_not_verified = 2

SOURCE未検証という別の理由でclosure_eligible=falseになるものの、完了済みtraceの未解析末尾を検証器は拒否していません。

最小修正条件

Malformed WICの終端probe_exit.complete=trueを受理する場合は、以下を追加してください。

Python
実行
need(
    record.get("trace_complete") is True
    and record.get("trace_partial_bytes") == 0
    and record["trace_utf8"].endswith("\n"),
    "malformed_complete_trace_has_partial_tail"
)

これに対応するcoherent mutation負例を追加してください。malformed_truncatedのdecoded経路と、malformed_bad_lengthのcorrupt経路の双方を対象にします。

W2の停止途中traceには一律適用せず、完了したmalformed WIC traceだけを対象としてください。

WIC/GDI+ probe、crates/media、Runtime、既存W1～W7の変更は不要です。
