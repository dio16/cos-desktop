## 1. 本タスクを選択した理由

MP-IMG2のhard prerequisitesは以下である。

- MP-IMG1: A/B TECHNICALLY COMPLETE
- MP-SEC3: Desktop-local admission TECHNICALLY COMPLETE

MP-IMG2-W1では実WICによるpre-materialization
admissionと予算境界を確認した。

しかしDC-MP-IMG2のDecode Exitは未達である。

特に以下が残っている。

- 実デコード時の資源観測
- 複数デコード実行時の同時常駐量
- decoder内部scratchとconversionの帰属
- cancellationの実際の到達境界
- codec別の資源・能力・fallback判断
- decoder採用表の実測裏付け

したがってW2では、W1で成立した実WIC経路を
継続使用し、実デコードの資源とキャンセルを
観測可能な範囲で実証する。

目的は「資源とキャンセルに関する実測の追加」であり、
未取得の全能力を一括してPASSにすることではない。

MP-IMG3 Uploadには着手しない。

## 4. 実装目的

既存WIC decoderを実際に動作させた際の、

A. デコード段階の到達時刻
B. 明示的に計算・予約できるバイト数
C. OSから観測できるprocess memory
D. 同時実行数と同時常駐量の観測
E. cancellation要求から停止・回収までの状態
F. 失敗時の出力非公開とcleanup

を、同一入力・同一候補・同一予算に結び付けて記録する。

重要:

「process全体のmemoryが観測できた」
ことは
「decoder内部scratch peakが分かった」
ことを意味しない。

両者を別フィールド・別判定とする。

## 6. Decode stageの観測

既存の正常WIC実行を保持したまま、
明示opt-inの計測経路を追加する。

測定可能なstage:

- process start
- input opened / metadata available
- admission started / admitted / refused
- OnLoad entered
- OnLoad returned
- conversion entered / returned
- CopyPixels entered / returned
- output encode entered / returned
- process exit
- cancellation requested / observed
- direct-child termination / reap

使用できないstageはNOT_MEASUREDとする。

時計:
- 1プロセス内の期間計測はmonotonic clock
- cross-process相関は明示したclock domainで記録
- 非共通clockの時刻を単純減算しない
- timestampの単位と観測者を必ず記録

実測したstageと、sourceから推定したstageを
同じobservedフィールドに混在させない。

Opt-in計測を使わない通常のWIC probeの
stdout JSON、argv、exit semantics、legacy behaviorは
変更しない。

計測用sidecarを追加する場合:
- operatorが指定した新規owned work root内だけ
- メディアmetadataからパスを生成しない
- 追記量・サイズ・行数に有限上限を設ける
- 不完全traceはcompleteと扱わない
- 出力を公開する前にadmissionを必ず通す

## 7. Memory accounting

少なくとも次の値を区別する。

1. encoded_input_bytes
2. admitted_decoded_bytes
3. BGRA32 conversion destination bytes
4. explicitly declared scratch allowance
5. explicit known reservations
6. observed process working set
7. observed process private bytes
8. decoder_internal_scratch_peak
9. observed concurrent process aggregate
10. actually proven peak concurrent allocation

各フィールドに次の情報を付与する。

- valueまたはnull
- unit
- source
- measurement_method
- observed / declared / derived / not_measured
- sample_count
- completeness
- measurement limitations

WIC内部の領域を直接観測できない場合、
decoder_internal_scratch_peak=nullとする。

sampled process private bytesを
decoder scratchへ代入しない。

working setの最大サンプル値は
sampled_lower_boundであり、
真のpeakとは区別する。

旧scratch_max_bytesはcapture-file accountingのまま。
decoder scratchへ意味変更しない。

追加のOS memory samplingには、
Windowsの既存標準API/ツールと
標準ライブラリのみ使用する。

sampling_disabled、sampler_unavailable、
process_identity_unverified、sampling_incomplete、
sampled_lower_boundを明示的に区別する。

process IDの再利用、異なるprocess lifetime、
サンプル欠落を無視した総和を作らない。

同時実行の集計では、同一時点に観測された
識別済みprocessだけを対象とする。

個別processの別時刻の最大値を足して、
同時実測peakと称してはならない。

## 8. 有界な実Windows入力と同時実行

Windows上の実WICで実行する。

既存のW1 fixture generatorとpixel oracleを再利用する。

実入力はローカルで生成したPNG/BMP/JPEGとし、
各入力のbyte length、SHA256、寸法、format、
生成方法を記録する。

基礎入力:
- small PNG
- small BMP
- small JPEG
- bounded 256×256 preview-class
- bounded 1024×1024 detail-test-class
- declared oversized PNG
- malformed/unsupported input

最大3同時実行。

構成:
- preview-class 2件
- detail-test-class 1件

これはADR-0008の
「2 thumbnail/preview + 1 full/tile」
という宣言された同時実行上限に対応した
限定stress configurationである。

ただし1024×1024のdetail-testを
16K full-detail capabilityとは呼ばない。

各実行は必ず:
- pre-materialization admission
- 有限の単体deadline
- 有限の総実行deadline
- 最大case数
- 最大output bytes
- 最大work-root bytes
- 最大trace records
- 最大sampling count
を持つ。

上限値はmanifestへ保存する。

ratified defaultを変更せず、
安全な狭いoverrideを使う。

全体予算の超過、admission failure、cancel、
timeoutではfail-closedとする。

16K画像のフルデコード、大量のOS memory確保、
無制限process起動は実行しない。

## 9. Cancellationの実測

以下を分離する。

A. admission前のcancel
B. OnLoad開始前のcancel
C. OnLoad実行中に外部から要求されたcancel
D. OnLoad終了後のcancel
E. timeout/kill/reap
F. output publication前のcancel

Cが実際に到達できたかをtraceで判定する。

WIC OnLoadが同期的で協調中断できない場合、
process terminationによる停止と明記する。

in-decoder cooperative cancellationを
実装したとは記録しない。

少なくとも次を検証する。

- cancel要求時刻が記録される
- process identityが検証される
- direct childの停止・回収を確認する
- cancel後のdecoded successを公開しない
- partial outputはvalid outputにならない
- timeoutと正常cancelを別理由として記録
- cancelの反復で残存processが増えない
- cancellation未到達時はNOT_MEASUREDとする

危険な入力をデコードし続けて
キャンセル能力を証明しようとしない。

## 11. 独立検証と負例

新しいW2 verifierには、
sourceとrecordから独立した期待値検査を設ける。

最低限の負例:
- record欠落
- 空観測
- case ID重複/欠落
- source digest不一致
- process identity不一致
- 異なるclock domainの不正な比較
- trace stage逆転
- admission拒否後のmaterialization
- 出力欠落なのにdecoded成功
- cancellation後の成功公開
- memory observation欠落なのにpeakを報告
- 異時刻process maximaの不正な合算
- sampler異常なのにmeasured成功
- reportまたはwork-root上限超過
- outputの途中書込み/不完全record
- cancel/timeout後のcleanup不一致

必須observationsの欠落は
all([])型のfalse-greenを許さない。

同じ入力に対する構造的・算術的な結果は
独立に再現できること。

OS sampling値やwall timeが変動する場合は、
bit-identicalを強制せず、
非決定部分を宣言して比較対象から分離する。

観測された計測値を書き換えて
digest一致を作ってはならない。

## 13. 独立Refine Gate

Taskernは実行計画まで。
Refineは現Coding Agentが確定した
製品SOURCE commitの独立Gateだけに使用する。

手順:

1. SOURCE・Native evidenceを固定
2. candidate SHAを記録
3. git tree cleanを確認
4. Refine 0.3.1の既存正典設定を確認
5. QualityとBuildを独立実行
6. status / inspect / verifyを取得
7. candidate_sha256を相関
8. required checksとartifact tuplesを相関
9. cleanupとowner stateを確認

Gateは固定candidate SHAに対して実行する。

SUCCEEDED、全必須check pass、
gate.verify成功を必要条件とする。

preflight UNKNOWNはUNKNOWNのまま残す。

Gate FAILED時は失敗原因を修正し、
新SOURCE候補を固定して新Gateを実行する。

同じSOURCE候補に対して、
成功済みの同一仕様Gateを
文書修正だけの理由で再実行しない。

Taskernのplanや他リポジトリに
Refine Gateを流用しない。
