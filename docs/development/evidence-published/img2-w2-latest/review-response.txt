3. 新規指摘
A-W2-01 — 終了済みworkerをcancelledとして記録できる競合条件

種別：ACTIONABLE NON-BLOCKING

対象：apps/desktop/devtools/img2/w2_resource_matrix.py:204–215、229–259

Worker.stop()は、キャンセル要求時刻とmethod="direct_child_terminate_wait"を設定した後、次の条件でkillを省略します。

Python
実行
if self.proc.poll() is None:
    self.proc.kill()
self.proc.wait(timeout=5)

つまり、stop()呼出し直前にworkerが正常終了していた場合でも、killを実行せずにrequested_ns、observed_ns、waited=Trueを記録します。

その後のWorker.finish()は、requested_nsが存在するだけでcancelledへ分類し、既存出力があれば削除します。

独立再現： すでにexit 0で終了した模擬processをWorker.stop()へ渡したところ、kill呼出し0回にもかかわらず、method="direct_child_terminate_wait"のcancellation記録が生成されました。

さらに、提出されたnative-matrix.jsonのonload_3についてexit codeだけを0に変更しても、現在のw2_resource_verify.verify()はok=trueを返しました。したがって、検証器もこの競合を検出できません。

これは、実Nativeのonload_3が誤分類だったと断定する指摘ではありません。実記録はexit 1であり、killされた可能性があります。しかし、そのことを証明するフィールドが記録されていないため、終了とキャンセルの競合を区別できません。

修正条件： 子プロセスの実際の終了状態を確認し、停止要求、kill実施、回収、実際の終了結果を別々に記録してください。停止要求前に終了済みなら、実際の結果を保持し、cancelled成功に分類しないこと。killと自然終了が競合した場合も、停止が確認できなければNOT_VERIFIED等の閉じた状態で扱ってください。

回帰テストには、少なくとも「停止要求前にexit 0」「停止要求前にexit 1」「killが実行された正常なcancel」「killと自然終了の競合」を含めてください。検証器は、実際の停止操作・結果が欠落したcancellation成功を拒否する必要があります。

この問題は実測runnerの終了分類に限定されます。WIC admission、DecodeBudget、DC-MP-IMG2、既存の4つの人工hold境界を再設計する必要はありません。
