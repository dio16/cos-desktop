## 6. 実Bgr565 fixtureの生成

Python標準ライブラリなど既存承認済み環境だけを使い、
再現可能な16-bit BMP fixtureを生成する。

BMPにはBI_BITFIELDSを使用し、
RGB channel masksを明示する。

R: 0xF800
G: 0x07E0
B: 0x001F

検証する入力:
1. black / white / red / green / blue
2. 各channelの中間値
3. 1-pixel幅
4. odd-width / row padding
5. 複数行
6. top-down / bottom-up
7. at-budget boundary
8. one-unit-over-budget boundary
9. truncated payload
10. malformed channel masks
11. inconsistent metadata
12. unsupported format declaration

各fixtureに次を記録する。

- generation algorithm
- dimensions
- row order
- bit depth
- channel masks
- row stride
- declared source bytes
- encoded bytes
- SHA256
- expected decoded pixel values

入力は実ファイルとして生成する。

同一色の別表現を比較するだけではなく、
独立に計算したBgr565→RGBA期待値を保持する。

## 7. 実WIC admissionとdecode

既存のwic_probe.ps1を使用する。

必須条件:

- WICが報告した実source pixel formatを記録する
- Bgr565との一致を確認する
- ファイル名やBMP宣言だけでBgr565認定しない
- maximum channel bit depth=6
- source bits-per-pixel=16
- width、height、max_pixelsを検証
- row-wise byte arithmeticを維持
- decoded/conversion/scratch予算を事前検証
- OnLoad materialization前のadmissionを維持

実source pixel formatがBgr565でない場合:
- 実際のWIC formatを記録
- Bgr565 capabilityをPASSにしない
- unsupported/mapped/convertedの実態を区別する
- 代替formatへ黙って再分類しない

byte accountingでは、
単純なwidth×height×2だけに依存せず、
既存W1のrow-wise算術を使用する。

BMPのencoded row strideと
WIC内部stride/scratchは別の概念として記録する。

内部strideを実測できなければNOT_MEASUREDとする。

## 8. Pixel oracle

実WICでBgr565をデコードし、
既存のbounded canonical-PNG出力経路を使用する。

独立oracleは元BMPのbitfield payloadから
channel値を読み取り、期待RGBAを算出する。

検証内容:
- R/G/B channel mask
- 5-bit/6-bitの抽出
- 8-bitへの展開規則
- row order
- row padding
- alpha
- width/height
- output PNG CRC/inflate/filter
- RGBA全画素

WICの色変換や量子化に差がある場合、
その差を測定して記録する。

期待値を実出力から逆算して
一致結果を作ってはならない。

完全一致を主張する場合は、
独立期待値とのbyte単位比較を必須とする。

完全一致しない場合も、
差の位置・値・変換条件を記録し、
unverifiedをPASSへ変更しない。
