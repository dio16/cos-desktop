4. 残存指摘
A-W6-01 — workerのidentity確認状態をfalseにしても正常認定される

分類：ACTIONABLE NON-BLOCKING

対象：apps/desktop/devtools/img2/w6_memory_verify.py:130–143

現在の_worker()はPID、開始UTC ticks、executable SHA256、input SHA256を照合します。

しかし、W6 producerが記録しているidentity_verifiedを検証していません。

独立再現：

Python
実行
worker["identity_verified"] = False

正常decoded workerでも、before-OnLoad停止workerでも、構造検証器はok=trueを返します。

さらに、次の改変も受理されました。

Python
実行
worker["boundary_hold_is_instrumentation"] = False

前者はworker identityの確認が成立していないと明示された記録を受理する問題です。後者はstageの人工hold証拠とworker-levelの分類が矛盾している問題です。

実Native記録は両フィールドともtrueです。

最小修正条件

_worker()に以下を必須化してください。

Python
実行
need(
    w["identity_verified"] is True,
    "worker_identity_not_verified"
)
need(
    w["boundary_hold_is_instrumentation"] is True,
    "hold_classification_mismatch"
)

decodedおよびcancel/timeoutでの個別負例を追加してください。Sampler、WIC probe、Windows APIの変更は不要です。
